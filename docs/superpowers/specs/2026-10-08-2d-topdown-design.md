# 2D 탑다운 도트 전환 — 설계

- 작성일: 2026-10-08
- 상태: 설계 확정 대기
- 배경: 3D 캐릭터 등신을 늘리는 시험(`spike/character-proportions` 브랜치, `2026-10-08-character-proportions-spike.md`)이 에셋 준비·뼈대·애니메이션 작업 때문에 매번 오래 걸렸다. 그림을 바꾸는 비용이 작은 2D 도트로 옮긴다.

## 1. 목표와 성공 기준

- 「아코스의 여정」 외전을 **2D 탑다운 도트 RPG**로 바꾼다. 조작은 포켓몬 방식(4방향 칸 이동, 확인·취소 버튼).
- 이야기(대사·선택지·기억 조각·저장)는 지금 것을 그대로 쓴다.
- **전투 비중을 높인다**: 필드 전투를 늘리고, 적 3종과 강베기, 이어지는 체력을 더한다.
- 성공 기준
  1. 처음부터 엔딩까지 2D로 끝까지 할 수 있다(PC 가로, 휴대폰 세로·가로).
  2. 맵·대사를 고치면 새로고침 한 번으로 바로 확인된다(빌드 없음).
  3. 아코스·아이온 그림을 나중에 표 두 줄만 바꿔 교체할 수 있다.
  4. `npm test`가 규칙·맵을 검사한다.

## 2. 하지 않는 것

- 보스전(이야기를 건드리므로 1·2단계가 끝난 뒤 따로 정한다)
- 아코스·아이온 전용 그림(1·2단계는 무료 에셋으로 끝까지. 나중에 힉스필드로 그려 나머지 에셋 느낌에 맞춘다)
- 맵 편집기(Tiled 등), 게임 라이브러리(Phaser 등), 빌드 도구

## 3. 단계

| 단계 | 내용 | 끝났을 때 |
|---|---|---|
| 1단계 | 지금 내용 그대로 2D로 옮긴다(지역 3곳, 전투 3번) | 처음부터 엔딩까지 2D로 된다 |
| 2단계 | 필드 전투, 체력 이어짐·약초, 적 3종, 강베기 | 전투가 늘어난 판으로 끝까지 된다 |
| 나중 | 아코스·아이온 그림 교체, 보스전 검토 | — |

## 4. 에셋

Kenney의 16×16 도트 팩 4개(모두 CC0, 같은 작가라 그림체가 맞는다). 타일시트 PNG(`tilemap_packed.png`, 각 5KB 남짓)만 `assets/kenney/<팩>.png`로 넣는다.

| 팩 | 쓰는 것 |
|---|---|
| Tiny Town | 잔디·흙길, 초록·단풍 나무, 지붕·벽·문, 성벽·성문, 울타리, 우물, 표지판, 통 |
| Tiny Dungeon | 인물(기사·병사·마법사·노인 등), 적(유령·박쥐 등 — 역병 적은 인물을 검게 칠해 쓸 수도 있다), 돌바닥, 횃불 |
| Tiny Battle | 연못·강·물가, 폭포처럼 보이는 물 타일 |
| Tiny Farm | 앙상한 나무(역병 왕도), 바위, 건초·여물통 |

- 없는 것: 천막·침대·모닥불·괘종시계. 비슷한 타일로 대신하거나 Canvas로 몇 픽셀 직접 그린다(모닥불은 깜빡이는 점 몇 개).
- 어느 기호가 몇 번 타일인지는 `data/tiles.js`, 인물·적이 몇 번 칸인지는 `data/sprites.js`에 둔다. **그림 교체는 이 두 파일만 고친다.**

## 6. 좌표와 맵

- **게임 좌표 1 = 타일 1칸(16px).** 지금의 `x, z`가 화면의 가로·세로가 된다(`z`가 작을수록 화면 위 = 북쪽). 전투 거리·트리거 반경 같은 숫자는 같은 단위로 그대로 쓴다.
- 인물은 칸 중심(정수 좌표)에 선다.
- 지역마다 `map`은 문자열 배열이다. 맨 윗줄 맨 왼쪽 칸이 `(bounds.minX, bounds.minZ)`.

```js
map: [
  '########',
  '#..TT..#',
  '#..H...#',   // H = 3×3 집 도장(이 칸이 도장의 왼쪽 위)
  '#~~....#',
],
```

- 기호 하나가 타일 하나이거나, 여러 칸짜리 **도장**(집·성·성문·탑)이다. 바닥 타일은 기호마다 정해 둔다(예: 나무 칸의 바닥은 잔디).
- 막힌 칸: 벽·나무·물·건물·인물. 조건부 막힘(성문 `blockers`)은 지금처럼 조건으로 켜고 끈다.

## 7. 화면

- 짧은 쪽에 약 12칸(192px)이 보이도록 작은 해상도로 그린 뒤 **정수 배율로 확대**한다(`imageSmoothingEnabled = false`, CSS `image-rendering: pixelated`). 남는 가장자리는 조금 더 보이게 한다.
- 카메라는 아코스를 따라가고 맵 가장자리에서 멈춘다.
- 그리는 순서: 바닥 → (나무·건물·인물·적을 아래쪽 줄부터) → 효과. 나무 뒤로 가면 가려진다.
- 조명: 지역 분위기(`night`·`dusk`·`day`·`dawn`)마다 화면 전체에 색을 덧씌운다. 밤에는 가로등·모닥불 둘레만 둥글게 밝힌다. 멈춘 시간 연출은 지금 `ui.setFrozenLook`을 그대로 쓴다.
- 인물은 한 장짜리 스프라이트다. 왼쪽을 보면 좌우로 뒤집고, 걸을 때는 1~2px 통통 튄다.
- 전투 연출: 베기는 앞쪽에 흰 반달 궤적, 공격 준비는 붉은 깜빡임, 맞으면 하얀 번쩍임, 쓰러지면 깜빡이며 사라진다.

## 8. 조작 (포켓몬 방식)

| 키 | 탐험·대화 | 전투 |
|---|---|---|
| 방향키 | 4방향 칸 이동(누르고 있으면 이어 걷기, 짧게 누르면 방향만 바꿈), 선택지 고르기 | 이동 |
| Z (확인) | 말 걸기·살펴보기, 대사 넘기기, 선택지 결정 | 베기(2단계: 길게 눌렀다 떼면 강베기) |
| X (취소) | 누르고 있으면 달리기, 대사 빨리 넘기기 | 피하기 |
| A / S | 비워 둔다 | 비워 둔다 |

- 숫자 1~3으로 선택지를 고르는 것과 마우스 클릭으로 대사 넘기기는 남겨 둔다(있던 기능이고 비용이 없다).
- 걷기 4칸/초, 달리기 8칸/초(해 보고 조정).
- **말 걸기**: 자동이 아닌 트리거는 "바라보는 앞 칸의 중심에서 1.5칸 안에 트리거 중심이 있을 때" Z로 연다. 그럴 때 아코스 머리 위에 작은 Z 표시를 띄운다. 자동 트리거(`auto`)는 지금처럼 반경 `r` 안에 들어서면 열린다.
- **휴대폰**: 왼쪽 아래 조이스틱(가장 많이 기운 축 하나만 읽어 4방향), 오른쪽 아래 Ⓩ·Ⓧ 버튼을 탐험·대화·전투 내내 띄운다. 길게 누르기도 키와 같게 동작한다. 지금의 [베기]·[피하기]·말 걸기 안내 버튼은 없앤다.

## 9. 전투

### 1단계 — 지금 규칙 그대로
- `createFight`·`update`·`swing`·`dodge`를 그대로 쓴다. 아코스의 `facing`은 4방향 각도(0, ±π/2, π).
- 피하기: 무적 0.4초 + 누르고 있는 방향(없으면 바라보는 반대쪽)으로 1칸 빠르게 이동(막히면 제자리).

### 2단계 — 늘리기

**필드 전투**
- `FIGHTS`에 `field: { region, x, z, r }`를 가진 무리를 더한다. 아코스가 `r` 안에 들어오면 그 자리에서 전투가 시작된다(순간이동·화면 전환 없음). 조건 `if`를 붙일 수 있다.
- 이기면 지금처럼 `won:<id>`를 남기고 다시 나오지 않는다. `then`(이긴 뒤 대사)은 있어도 되고 없어도 된다.
- 지역 1(성문 밖 길)과 지역 2(골짜기, 날짜별)에 4~5무리. 지역 3(새벽의 다리)에는 넣지 않는다. 개수는 해 보고 조정한다.

**적 3종**(`enemies`의 세 번째 값으로 종류를 준다. 없으면 걸음꾼)

| 종류 | 움직임 | 체력 |
|---|---|---|
| 걸음꾼 | 지금 적 그대로(다가와 0.5초 준비 후 1피해) | 3 |
| 투척꾼 | 4~6칸 거리를 유지하며 1.5초마다 오물을 던진다(초당 6칸, 맞으면 1피해). 3칸 안으로 오면 물러난다 | 2 |
| 돌진꾼 | 아코스와 같은 줄(가로나 세로)에 서면 0.7초 준비 후 초당 12칸으로 최대 6칸 돌진(닿으면 1피해). 막힌 칸에 부딪히면 1.5초 기절 | 4 |

- 오물·돌진도 피하기 무적 중이면 맞지 않는다. 막힌 칸 판정을 쓰려고 `update`가 `blocked(x, z)` 함수를 받는다.

**강베기**: Z를 0.6초 이상 누르고 있다 떼면 범위 2.8칸·반각 100°에 2피해. 모으는 동안 걷는 속도가 절반.

**체력**: 전투 사이에도 이어진다(`state.hp`). 지역에 들어갈 때 가득 차고, 맵의 약초를 살펴보면 +1(약초마다 한 번, `done:<id>`). 쓰러지면 지금처럼 그 전투를 체력 가득으로 다시 시작한다.

수치는 모두 초안이다. `combat.js` 맨 위 상수로 두고 해 보며 조정한다.

## 10. 저장

- 형식은 지금과 같다(`v: 1`). 2단계에서 `hp`가 생기며, 없으면 최대 체력으로 본다. 지역·날짜·플래그가 같으므로 3D 판의 저장도 그대로 이어서 할 수 있다.

## 11. 테스트

- 그대로 둘 것: `story`, `combat`(1단계), `content`(대본 검사), `region`, `touch`(바뀐 부분만 고침)
- 새로: `map`(기호 해석, 도장, 막힌 칸), `player`(`step`: 이동·방향 바꾸기·막힘·달리기), 지역 맵 검사
  - 모든 줄의 길이가 같고, 모르는 기호가 없다
  - 시작 칸·트리거·인물 칸이 맵 안에 있고, 시작 칸이 막혀 있지 않다
  - 시작 칸에서 모든 트리거에 걸어서 갈 수 있다(조건부 막힘은 열린 것으로 보고 칸 탐색)
- 2단계: 투척꾼·돌진꾼·강베기·체력 이어짐 규칙 테스트
- 화면은 단계마다 스크린샷 한두 장으로 확인한다.

## 12. 작업 순서

1. 도트 화면 뼈대: 왕도 맵 하나, 아코스 칸 이동, 카메라 → 스크린샷으로 확인
2. 이야기 연결: 말 걸기·대화·선택지·저장, 지역 1~3 맵, 전투 3번 → **1단계 끝**(처음부터 엔딩까지)
3. 3D 걷어 내기: KayKit·Three.js·3D 도구와 테스트 삭제, README·CREDITS 정리
4. 필드 전투 + 체력 이어짐 + 약초
5. 적 3종 + 강베기 → **2단계 끝**
6. (나중) 아코스·아이온 그림 교체

작업은 `2d-topdown` 브랜치에서 한다.
