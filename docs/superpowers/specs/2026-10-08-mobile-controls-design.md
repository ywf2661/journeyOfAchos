# 모바일 조작과 모바일 손질 — 설계 문서

> 휴대폰·태블릿에서 터치만으로 「Journey of Achos」를 처음부터 엔딩까지 플레이할 수 있게 한다.
> 본편 스펙(`docs/superpowers/specs/2026-10-08-journey-of-achos-design.md`)에서 "첫 버전에서 제외"했던
> 모바일 터치 조작을 이번에 넣는다. 그 밖의 본편 스펙 내용은 그대로 유지한다.

- 작성일: 2026-10-08
- 접속 방법: GitHub Pages(`https://ywf2661.github.io/journeyOfAchos/`). Pages 켜기는 사용자가 저장소 설정에서 한다.

---

## 1. 목표와 범위

| 항목 | 결정 |
|---|---|
| 목표 | 휴대폰·태블릿에서 터치만으로 처음부터 엔딩까지 진행 |
| 조작 방식 | 떠다니는 가상 조이스틱 + 상황 버튼(라이브러리 없이 직접 구현) |
| 화면 방향 | 가로·세로 모두 지원 |
| 함께 손볼 것 | 휴대폰 화질 조정, 아이폰 소리, 안 쓰는 애니메이션 제거(첫 다운로드 절반) |
| PC | 조작·화면·화질 모두 지금과 같다 |

**제외**(나중에 추가 가능): 진동, 조작 감도·버튼 위치 설정, 화면 방향 잠금, 오프라인 실행(PWA), 텍스처 압축, fps를 재서 화질을 자동으로 바꾸는 기능.

### 조사로 확인한 사실 (휴대폰 흉내 Chrome, 844×390·390×844, 배율 3, 터치)
- 지금도 되는 것: 버튼 탭(타이틀·선택지·끝 화면), 대화창 탭으로 대사 넘기기, 손가락으로 끌어 시야 회전, 전투 중 화면 탭으로 베기, `(pointer: coarse)` 판별.
- 막히는 것: 이동(WASD뿐), 말 걸기(E), 피하기(Space), 달리기(Shift). 조작 안내가 키보드 기준("[E] …", "(WASD로 걷고…)").
- 용량: 지역 1 진입 시 19.7MB(지역 2 +3.7MB, 지역 3 +0.1MB). 캐릭터 GLB 6개가 대부분이다(각 3.4~4.6MB). 기사 모델의 애니메이션은 76개·1.6MB인데 게임이 쓰는 것은 0.19MB, 적 모델은 95개·2.5MB 중 0.20MB다.
- 휴대폰은 화면 배율이 3이라 지금 설정(상한 2배)으로는 캔버스를 1688×780으로 그린다.

## 2. 터치 기기 판별

- 부팅할 때 한 번 `matchMedia('(pointer: coarse)').matches`로 정한다 → `TOUCH`.
- `TOUCH`면 `<body>`에 `touch` 클래스를 붙이고, 터치 조작 화면을 만든다.
- 상태 플래그 `touch`: 상태를 새로 만들거나 불러온 직후(부팅 때) `TOUCH`에 맞춰 켜거나 끈다. 저장 데이터에 남아 있어도 다음 부팅에서 덮어쓴다. 대본의 안내 문구가 이 플래그로 갈린다(5장).
- 주 입력이 마우스인 터치스크린 노트북은 PC로 취급한다.

---

## 3. 화면 배치와 동작

### 3-1. 조이스틱 (`src/touch.js`)
- 받는 영역: 화면 왼쪽 절반(캔버스 위, 대화창·타이틀 같은 오버레이 아래).
- 떠다니는 방식: 손가락을 댄 곳이 중심이 되고, 손잡이는 반지름 **R = 48px** 원 안에서 손가락을 따라간다. 안 쓸 때는 왼쪽 아래(안전 영역 안쪽)에 흐린 원을 그려 위치만 알려 준다.
- 출력: `{ f, r }` — `r = dx / R`, `f = -dy / R`, 길이가 1을 넘으면 1로 자른다. 손을 떼면 `null`.
- 한 손가락만 따라간다(포인터 캡처). 다른 손가락은 무시한다.

### 3-2. 걷기·달리기 판정
- 데드존: 기울기 길이 < **0.15**면 멈춤.
- 달리기: 기울기 길이 ≥ **0.85**. 그 사이는 걷기. 속도는 지금처럼 걷기·달리기 두 단계다.

### 3-3. 시야
- 오른쪽 절반을 끌면 회전한다(지금과 같다).
- `player.js`가 드래그를 시작한 포인터 id를 기억해, 다른 손가락이 끼어들어도 엉키지 않는다.
- 버튼이 눌려 있지 않은 `pointermove`는 드래그를 끝낸다(창 전환 뒤 시야 회전이 붙어 남는 문제 방지 — 리뷰 M4).

### 3-4. 말 걸기
- 화면 아래 가운데의 안내(`#prompt`)를 `<button>`으로 바꾼다. 누르면 E와 같은 동작(`interact()`)을 한다. PC에서도 클릭할 수 있다.
- 글자: PC는 `[E] 폐하를 뵙는다`, 터치는 `폐하를 뵙는다`. "(되돌릴 수 없음)" 표시는 둘 다 그대로.

### 3-5. 전투 버튼
- 터치이고 전투 중일 때만 오른쪽 아래에 **[베기] [피하기]**. 베기 = `attack()`, 피하기 = `dodgeAction()`.
- 화면 탭으로 베기는 지금처럼 동작한다.

### 3-6. 표시 규칙
- `main.js`가 매 프레임 `document.body.dataset.mode = mode`를 쓴다.
- CSS로만 보인다/숨긴다:
  - `body.touch[data-mode="explore"]`: 조이스틱
  - `body.touch[data-mode="combat"]`: 조이스틱 + 전투 버튼
  - 그 밖의 모드(타이틀·로딩·대화·엔딩·오류): 조이스틱·전투 버튼 숨김
- 말 걸기 버튼은 지금처럼 탐험 중 근처에 트리거가 있을 때만 보인다(PC·터치 공통).

### 3-7. 터치 위생
- 버튼은 최소 56×56px.
- 조이스틱 영역 `touch-action: none`, 버튼·대화창 `touch-action: manipulation`(두 번 탭 확대 방지, 핀치 확대는 막지 않는다).
- 오버레이 글자 선택·길게 누르기 메뉴 끔(`user-select: none`, `-webkit-touch-callout: none`).
- `viewport-fit=cover`와 `env(safe-area-inset-*)`로 노치 영역을 피한다.

### 3-8. 세로 화면
- 창 크기가 바뀔 때 `camera.fov = innerHeight > innerWidth ? 70 : 55`.

## 4. 입력 경로 (코드 구조)

| 파일 | 바뀌는 것 |
|---|---|
| `src/geom.js` | `moveVector(axes, camYaw)` — 입력이 키 4개(켜짐/꺼짐)에서 기울기 `{ f, r }`(각 −1~1)로 바뀐다. 길이 < 0.15면 `null`, 아니면 길이 1 방향 |
| `src/player.js` | `setStick(axes \| null)` 추가. 조이스틱 값이 있으면 그것을, 없으면 키보드 축(`f = W−S`, `r = D−A`)을 쓴다. 달리기 = Shift 또는 기울기 ≥ 0.85. 회피 방향도 같은 경로. 포인터 id 추적(3-3) |
| `src/touch.js` (새 파일) | `createTouchControls({ onStick, onAttack, onDodge })` — 조이스틱·전투 버튼 DOM을 만들고 이벤트를 처리한다. three를 쓰지 않는다 |
| `src/main.js` | `interact()`·`dodgeAction()`으로 묶어 키보드와 버튼이 함께 부른다. `TOUCH` 판별, `touch` 플래그, `body.dataset.mode`, 세로 시야각, 화질 옵션, 프롬프트 글자(터치면 `[E]` 생략) |
| `src/ui.js` | 프롬프트 버튼 클릭을 `interact()`에 연결(`onPromptClick`), 소리 깨우기(6-2) |
| `src/world.js` | `buildRegion(scene, region, state, { shadowSize })` — 그림자 맵 크기를 옵션으로 받는다(기본 2048) |
| `index.html` | 조이스틱·전투 버튼 자리, `#prompt`를 `<button>`으로, 터치 CSS, `viewport-fit=cover` |
| `data/script.js` | 조작 안내 2줄을 터치용·키보드용 짝으로(5장) |

## 5. 조작 안내 문구

기존 대화 엔진의 조건 노드 짝(`if: 'touch'` 다음 `if: '!touch'`)을 쓴다. 엔진은 바꾸지 않는다.

| 위치 | 키보드(지금 그대로) | 터치(새로) |
|---|---|---|
| `r1_open` 마지막 줄 | (WASD로 걷고 Shift로 달린다. 마우스를 끌어 둘러본다. 가까이 가서 E로 말을 건다.) | (왼쪽 화면을 끌어 걷고, 끝까지 밀면 달린다. 오른쪽 화면을 끌어 둘러본다. 가까이 가서 아래에 뜨는 안내를 눌러 말을 건다.) |
| `r1_road` 셋째 줄 | (클릭으로 벤다. Space로 몸을 피한다. 마우스를 끌면 시야가 돈다.) | (화면을 탭하거나 [베기]로 벤다. [피하기]로 몸을 피한다.) |

## 6. 모바일 손질

### 6-1. 화질 (터치 기기에서만)
- 렌더러 배율 상한 2 → **1.5**.
- 그림자 맵 2048 → **1024**, 그림자 방식 `PCFSoftShadowMap` → `PCFShadowMap`.
- `buildRegion(scene, region, state, { shadowSize })`로 그림자 크기를 넘긴다.

### 6-2. 소리 (아이폰)
- `ui.js`가 `click`·`touchend`·`keydown` 때마다 소리 장치(AudioContext)를 만들거나 `resume()`한다. 이미 동작 중이면 아무것도 하지 않는다. 아이폰은 사용자 동작 안에서 깨워야 소리가 난다.

### 6-3. 안 쓰는 애니메이션 제거
- `data/models.js`에 `ANIMATIONS`(게임이 쓰는 10개): `Idle`, `Walking_A`, `Running_A`, `Dodge_Forward`, `1H_Melee_Attack_Slice_Horizontal`, `1H_Melee_Attack_Chop`, `Hit_A`, `Death_A`, `Lie_Idle`, `Sit_Floor_Idle`.
- `tools/slim-anims.mjs`
  - 순수 함수 `slimGlb(glb: Buffer, keep: string[]): Buffer`.
  - 순서: `keep`에 없는 애니메이션 삭제 → 남은 것(메시의 속성·인덱스·모프 타깃, 스킨의 역바인드 행렬, 남은 애니메이션의 입출력, 이미지)이 참조하는 accessor·bufferView만 남김 → 바이너리를 4바이트 정렬로 다시 이어 붙임 → 인덱스를 다시 매김 → GLB를 다시 씀.
  - bufferView를 참조하는 확장(예: Draco·meshopt 압축)이 있으면 오류로 멈춘다(KayKit 캐릭터에는 없다).
  - 이미 줄어 있으면 결과가 같다(두 번 돌려도 같은 파일).
  - 명령: `npm run slim-assets` — `MODELS` 중 `.glb` 파일을 줄여 덮어쓴다.
- `tools/fetch-assets.mjs`는 `.glb`를 받은 직후 같은 함수로 줄인다. 새로 받아도 결과가 같다.
- 예상: 지역 1 첫 다운로드 19.7MB → **약 10MB**.

## 7. 테스트

### 자동 (`npm test`)
- 이동 방향: 기울기 → 방향, 데드존, 대각선 정규화, 카메라 회전 반영.
- 플레이어: 조이스틱으로 걷기, 끝까지 밀면 달리기(달리기 속도), 손을 떼면 멈춤, 조이스틱이 없으면 키보드.
- 애니메이션 줄이기(실제 `Knight.glb`·`Skeleton_Minion.glb`로):
  - `keep`에 있는 애니메이션만 남는다.
  - 파일이 작아진다.
  - 메시·스킨 accessor의 바이트가 원본과 같다.
  - 모든 accessor·bufferView가 버퍼 범위 안에 있다.
  - 두 번 돌려도 같은 결과다.
- 저장소의 캐릭터 GLB 6개가 이미 줄어 있다(`ANIMATIONS`만 들어 있다).
- 코드(`src/*.js`의 `play(…)` 안 문자열, `data/regions.js`의 `anim`)가 쓰는 애니메이션이 모두 `ANIMATIONS`에 있다.
- 대본: 기존 무결성·완주 테스트 + `touch` 플래그를 켠 상태로도 완주. `touch`가 켜져 있으면 터치용 안내만, 꺼져 있으면 키보드용 안내만 나온다.

### 브라우저 (휴대폰 흉내 가로·세로 + PC)
- 조이스틱이 휴대폰에서만 보이고 PC에서는 안 보인다.
- 조이스틱으로 걷기·달리기, 오른쪽 끌기로 시야, 말 걸기 버튼, 전투 버튼(베기·피하기), 대화 중 숨김.
- 세로 화면 시야각, 기기별 안내 문구.
- 줄인 모델이 세 지역 모두에서 보이고 애니메이션이 동작한다(PC·휴대폰).

## 8. 완료 기준

1. 휴대폰 흉내 환경에서 터치만으로 각 구간(이동, 말 걸기, 선택지, 전투, 지역 전환, 엔딩)을 진행할 수 있다.
2. 지역 1 첫 다운로드가 11MB 이하다.
3. PC 조작·화면·화질은 지금과 같다.
4. 자동 테스트가 모두 통과한다.
5. 실기기 확인(아이폰 소리, 실제 fps, 조작감)은 사용자가 휴대폰에서 GitHub Pages로 한다.
